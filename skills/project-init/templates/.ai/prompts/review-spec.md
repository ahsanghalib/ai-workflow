# Review a Feature SPEC

Use `spec-review` for one exact SPEC and its current project context.

Check behavior completeness, actors, permissions, invariants, validation,
states, failures, edge cases, compatibility, and acceptance traceability.
Separate confirmed facts, assumptions, contradictions, stale details, and open
decisions. Do not create implementation steps, approve the SPEC, or change
application files. After the user accepts the SPEC, route to `project-init` for
PLAN creation; do not create or approve a PLAN during this review.
