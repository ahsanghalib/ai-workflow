# Project-Init Output Boundary

Project-init creates or reconciles repository controls. It does not create an
application or own a substantive work-request lifecycle.

## Allowed bootstrap outputs

After the relevant approval, the minimal scaffold may create missing:

- `AGENTS.md`;
- `SESSION_STATE.md`;
- `.ai/memory/`; and
- `docs/specs/`, or an explicitly approved existing SPEC source mapped with
  `--spec-dir`.

It may copy `.gitignore.template` to `.gitignore` only when no `.gitignore`
exists. Local `.git` metadata is separate and requires explicit approval for
the exact canonical target with `--init-git`.

Conditional architecture, decision, flow, schema, and rules documentation is
not generated by the bootstrap helper. The bundled conditional templates remain
available as reviewed starting points; create or adapt them only through the
owning workflow after the project has a demonstrated need.

## Forbidden outputs

Project-init never creates, copies, installs, or mutates:

- roadmap, plan, review, schema, user-flow, architecture, or decision
  templates;
- application source, routes, services, models, UI, or feature files;
- framework scaffolds, package manifests, lockfiles, or dependencies;
- migrations, seeds, generated ORM models, tables, or database data;
- Docker, CI, hosting, cloud, or environment provisioning;
- `.env`, credentials, tokens, private keys, or secret values; or
- commits, branches, remotes, pushes, fetches, issues, projects, deployments,
  publications, or production operations.

## Verification and handoff

The initializer is deterministic copy-if-missing scaffolding. For an existing
alternate SPEC source, it refuses to guess and requires an explicit mapping. A
repeated run against an unchanged minimal scaffold reports a no-op. The handoff
lists every created, preserved, skipped, blocked, and unresolved item and states
the absence of forbidden outputs and external mutations. Structural evidence does
not prove live harness, runtime, browser, provider, deployment, or remote
behavior.
