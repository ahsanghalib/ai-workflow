# Hooks and openings

Use this reference when the post needs deliberate opening options. A hook must
be supported by the post's evidence and actual point of view; it is not a
license for sensationalism.

## Opening principles

- Name a specific tension, decision, observed behavior, or reader problem.
- Make the promise narrower than or equal to what the post can support.
- Prefer a concrete detail over a generic claim about the future of AI.
- Use the user's actual experience only when it was supplied.
- Avoid fake certainty, manufactured urgency, bait-and-switch questions, and
  universal claims.

## Grounded patterns

Adapt these as starting shapes, not fill-in-the-blank copy:

- “The difficult part of [system] was not [obvious task]. It was [supported
  mechanism].”
- “We treated [decision] as a [category] problem. The evidence suggested it
  was really a [different category] problem.”
- “A larger [context/model/tool] does not automatically solve [failure mode].
  The missing step is [bounded mechanism].”
- “The useful question about [release or trend signal] is not ‘is it better?’
  It is ‘better for which task and under which constraint?’”
- “Before adding [tool or capability], check [specific boundary]. It changes
  the failure mode more than the feature list suggests.”
- “One practical distinction improved how I evaluated [topic]: [distinction].”
  Use only when the user supplied the experience.

## Alternative handling

Draft alternatives only when they test genuinely different entry points, such
as mechanism, reader problem, decision, evidence update, or counterpoint. Keep
alternatives outside the exact final post body in the post file. Do not create
several cosmetic rewrites and present them as strategic options.

## Anti-patterns

- “AI is changing everything.”
- “Nobody is talking about this.”
- “This one trick will 10x your productivity.”
- a dramatic question whose answer is unrelated to the post;
- a copied headline or lightly reworded prior post;
- an opening that implies a personal result the user did not provide.

If the strongest opening is a modest, precise statement, use it. Precision is
more valuable than manufactured curiosity.
