# LinkedIn post formats

Choose one format that matches the evidence, audience, and requested objective.
The format is a reasoning aid, not a promise of reach or engagement.

## Formats

### Build lesson or decision record

Use when the user supplied a real build, decision, tradeoff, or failure.

Shape: context → decision or failure → mechanism → what changed → bounded
lesson. Keep first-person claims limited to what the user actually provided.

### Technical explanation

Use when the reader needs a clear model of how something works.

Shape: observed problem → mechanism → concrete example → limitation → takeaway.
Define terms before compressing them into shorthand.

### Problem, mechanism, implication

Use for a focused technical or product observation.

Shape: specific problem → why the default fails → mechanism → practical
implication. Avoid turning a narrow mechanism into a universal prescription.

### Evidence-backed observation

Use for a current release, paper, standard, benchmark, or multi-source signal.

Shape: what changed or was observed → evidence and date → interpretation →
uncertainty → reader implication. Label a signal as a signal rather than a
trend when the evidence is limited.

### Bounded project update

Use when the user has an actual project state to share.

Shape: what was attempted → current state → lesson or constraint → next
measured step. Never convert a plan, prototype, or aspiration into a shipped
outcome.

### Respectful counterpoint

Use when evidence supports a narrower view than a popular claim.

Shape: common assumption → where it holds → where it breaks → evidence → more
useful rule. Critique the claim or mechanism, not a person or community.

### Handoff to an approved longer source

Use only when the user has approved the article, repository, or other source.

Shape: reader problem → useful insight → what the longer source contains →
clear, non-hyped handoff. Do not imply that an unpublished or planned article
already exists.

## Selection rules

- Select one primary reader and one core takeaway.
- Prefer a concrete mechanism, decision, example, or limitation over a generic
  summary.
- Keep evidence and interpretation visibly distinct.
- Use a question only when it is a real reader-relevant question, not a generic
  engagement prompt.
- End with an implication, bounded next step, or honest question. A CTA is
  optional and must not overpromise.
- Do not force a post into a format that the evidence cannot support.

## Draft shape

Use this as a flexible sequence:

1. opening that names the specific tension, observation, or promise;
2. context that lets the intended reader orient quickly;
3. mechanism, evidence, example, or decision;
4. limitation, caveat, or counterpoint;
5. practical takeaway and optional question or approved handoff.

Use short paragraphs and deliberate line breaks for readability. Do not use a
universal word count, hashtag count, or formula as a quality guarantee.
